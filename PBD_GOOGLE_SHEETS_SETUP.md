# Integrasi PBD SimpulLoka V9 — panduan pemilik akaun Google

Status: versi pembangunan diluluskan untuk disimpan pada branch `work` bagi ujian localhost. Pemilik memaklumkan lapan tab dan Web App Google sudah disediakan; sambungan hujung ke hujung daripada aplikasi BELUM disahkan. Tiada deployment hosting dilakukan. Jangan gunakan data murid sebenar untuk konfigurasi awal. Semua preview/simulasi berlabel SIMULASI, bukan bukti sambungan Google.

## Seni bina minimum

Pelayar murid → proksi student sedia ada → Apps Script V9 → Murid/KemajuanLoka sedia ada + dua tab PBD. Pelayar guru → gateway same-origin `teacher-records` → Apps Script dengan rahsia proksi → dua tab yang sama. Gateway ialah modul Node yang digunakan oleh pelayan setempat dan adapter Netlify pada masa hadapan. Tiada pangkalan data kemajuan kedua.

Satu kod laluan guru sahaja. Hash scrypt disemak pada gateway (N=65536, r=8, p=1, salt rawak). Apps Script menyimpan sesi token-hash dan had percubaan dalam Script Properties di bawah LockService, dikongsi merentas instance gateway. Bukan perlindungan UI dan bukan Map sementara. Tiada kod/token guru localStorage. Cookie production HttpOnly/Secure/SameSite=Strict/Path=/, tamat tetap 30 minit. POST hanya JSON daripada Origin same-origin yang dikonfigurasi. Setiap operasi senarai/penilaian menyemak sesi pada pelayan; write menyemak semula dalam lock. Logout membatalkan sesi; kod editor `revokePbdTeacherSessions()` membatalkan semua sesi selepas pertukaran kod/insiden.

Had log masuk: 5 percubaan setiap cap IP terhash dalam 15 minit, 50 global; had 30 sesi aktif. Percubaan dikira sebelum scrypt, termasuk login berjaya. Had pengeluaran tiket: 60 per cap IP / 500 global setiap jam. Murid dalam NAT berkongsi had; semak kapasiti sebelum kegunaan sekolah. IP datang daripada context platform, bukan X-Forwarded-For pengguna; jika platform tidak memberikan IP, bucket “unknown” dikongsi, bukan dibenarkan tanpa had. Tiada IP mentah disimpan di Sheets. Kuota Apps Script/Script Properties tetap terpakai; sasaran kelas kecil, bukan skala terbuka tanpa had.

## Dua tab

**Ringkasan PBD:** A Tarikh Mula; B Masa Mula; C Nama Murid; D Kelas; E–J enam Loka; K Jumlah Loka Selesai; L Objektif 1; M Objektif 2; N Skor Penceritaan Lisan; O Skor Hasil Bertulis; P Ulasan Guru; Q Tarikh dan Masa Kemas Kini. R `recordId` dalaman disembunyikan. Nama/kelas bukan kunci unik. Tarikh/masa ialah Asia/Kuala_Lumpur, daripada createdAt tiket pelayan, bukan jam murid. N/O/P memaparkan penilaian guru terkini (bukan purata, TP atau skor permainan); semua penilaian Loka kekal dalam Butiran.

**Butiran Loka:** recordId, runId, lokaId, nama, kelas, nama Loka, tarikh, mula, tamat, selesai, item Objektif1, JSON jawapan/percubaan, status Objektif1, status Objektif2, skor lisan, skor bertulis, lima skor aspek rubrik, ulasan, kemas kini, versi penilaian, flag Pentas Cerita, sejarah penilaian. Pengecam dan metadata ini mengelakkan pendua/kehilangan evidens; tiada audio, token akses, IP atau TP disimpan dalam tab PBD.

Murid tidak mengisi ID/kod akses. Gunakan studentId tiket sedia ada. Retry permintaan tiket dengan requestToken automatik yang sama mengembalikan identiti yang sama. Memilih tiket baharu secara sengaja menghasilkan identiti baharu; jangan gabung murid bernama sama secara automatik. Keluar/refresh dengan tiket sah menyambung identiti dan runId aktif. Lawatan selepas Pentas Cerita mendapat runId baharu; permintaan berulang dengan runId/eventId sama tidak menggandakan baris/jawapan. Lawatan baharu tanpa jawapan tidak memadam evidens atau penilaian lama. Kemajuan selesai monotonik; Pentas Cerita hanya menandakan dilaksanakan, bukan Capai. Status/score/ulasan hanya ditulis guru. Konflik dua suntingan guru menghasilkan 409, bukan overwrite senyap. Sejarah 20 suntingan disimpan; setelah had, pentadbir perlu mengarkib sebelum suntingan lanjut. Maksimum 120 lawatan per tiket /80 respons setiap lawatan/500 rekod /1 juta aksara JSON pada paparan untuk menghadkan beban dan sel Sheets.

| 6 Cakap Besar | Stesen1 dialog bermegah (A); Stesen4 ayat tepat (A) | Uji kapal/bantuan Faris tidak dikira |

Jawapan dikira pada pelayan daripada pilihan item, bukan menerima flag `correct` murid. Setiap percubaan menyimpan pilihan, masa terima pelayan dan petunjuk item bahasa yang dilaporkan pelayar, bilangan maklum balas jawapan salah bagi item sama yang dikira pelayan, serta petunjuk permainan keseluruhan secara berasingan. Guru melihat percubaan pertama/terkini dan bantuan. Petunjuk permainan terdahulu tidak melabel jawapan pertama item lain sebagai bantuan bahasa. Bagi satu lawatan, jika mana-mana jawapan terkini salah → Belum Betul; jika kedua-dua item dijawab betul → Betul; jika belum lengkap atau tiada item → Tiada Evidens. Petunjuk tidak dipenalti tetapi dipaparkan. Ringkasan menyatakan bilangan Loka bagi setiap status daripada enam; tiada dakwaan penguasaan semua enam berdasarkan satu jawapan. Objektif2: Capai/Perlu Bimbingan/Belum Dinilai oleh guru sahaja, dengan pengesahan telah mendengar, lima skor aspek dan skor lisan profesional (bertulis pilihan). Tiada AI/TTS untuk menilai suara dan tiada syarat rakaman/penilaian guru untuk sijil/ganjaran.

## Langkah pemilik akaun — jangan kirim rahsia dalam chat

1. Buat **Google Sheets ujian kosong** dalam akaun sendiri. Kekalkan perkongsian private. Jangan pilih fail V7 atau data murid sebenar. Catat Spreadsheet ID secara setempat, bukan repository/chat.
2. Buka Extensions → Apps Script. Masukkan `backend/apps-script/Code.gs`, `backend/apps-script/teacher-records/Records.gs` dan `backend/apps-script/teacher-records/PbdModel.gs` sebagai tiga fail skrip dalam projek V9 yang sama. Jangan gandakan nama fail/fungsi atau salin fail V7.
3. Dalam Project Settings → Script Properties, isi `SPREADSHEET_ID` dengan ID ujian sebenar. Jana rahsia rawak sekurang-kurangnya 32 bait dengan pengurus rahsia/terminal setempat; isi `NETLIFY_PROXY_SECRET`. Jangan letak rahsia dalam kod atau log. Zona projek disyorkan Asia/Kuala_Lumpur; pemformatan rekod sudah menetapkannya secara eksplisit.
4. Jalankan `setupSimpulLoka()`, kemudian `setupPbdRecords()` dalam editor. Benarkan akses akaun selepas memeriksa skop yang diminta. Fungsi ini mengekalkan jadual asal dan menambah dua tab, memeriksa header serta berhenti jika skema berlainan. Ia tidak memadam data. Abaikan fungsi kata laluan lama `setTeacherPassword_` — gateway baharu tidak menggunakannya. Rekod PBD lama 1–4/TP tidak dimigrasi/ditukar kepada rubrik baharu secara tekaan. Rujukan Air Muka bagi setup baharu diselaraskan kepada maruah/harga diri; TetapanRujukan sedia ada tidak dioverwrite secara automatik dan perlu disemak pemilik jika pernah menggunakan versi lama. Kunci pentaksiran baharu menggunakan PbdModel, bukan jadual rujukan lama.
5. **Tindakan Google oleh pemilik diperlukan di sini:** untuk ujian HTTP sebenar, Apps Script perlu diterbitkan sebagai Web App bagi gateway, Execute as Me, akses mengikut polisi organisasi. Endpoint memeriksa proxy secret sebelum operasi, kemudian sesi guru/token murid. Jika polisi sekolah tidak membenarkan gateway mengakses Web App tanpa login Google interaktif, berhenti: jangan longgarkan polisi atau mendakwa sambungan berjaya. Seni bina alternatif minimum ialah gateway terlindung dengan Google Sheets API/akaun servis yang dipersetujui. Tiada URL rekaan diberikan, dan agen tidak menjalankan penerbitan ini.
6. Selepas tindakan Google diluluskan dan pemilik mempunyai URL `/exec` sebenar, buat `.env.pbd.local` sendiri (ignored). Gunakan senarai nama dalam `config/pbd.env.example`, isi `APPS_SCRIPT_URL`, `APPS_SCRIPT_PROXY_SECRET` (sama dengan Script Property). Hadkan kebenaran fail, jangan commit/kongsi nilainya.
7. Jalankan `npm run pbd:passcode` pada terminal sendiri. Taip satu kod 12–200 aksara; input tidak dipaparkan. Simpan hash yang dicetak sebagai `PBD_PASSCODE_HASH` dalam fail environment pelayan. Jangan kongsi kod atau hash dalam chat. Tetapkan `PBD_GATEWAY_ENABLED=true`. Kod laluan bukan ID/akaun murid.
8. `npm run build`, kemudian `node --env-file=.env.pbd.local scripts/pbd-dev-server.mjs`. Buka alamat loopback yang dicetak (lalai http://127.0.0.1:4180). Pelayan ini tidak deploy ke hosting. Cookie development HttpOnly/SameSite dibenarkan tanpa Secure hanya pada loopback dan apabila bukan environment Netlify. Akses telefon fizikal memerlukan HTTPS dipercayai; preview fasa ini menggunakan emulasi telefon.
9. Cipta tiket dengan **nama rekaan**, selesaikan satu Loka, log masuk guru, baca rekod, simpan penilaian, semak kedua-dua tab sebenar, ulang request/refresh, uji logout/expired/wrong code/CSRF dan putus sambungan. Hanya selepas semua ini lulus boleh sambungan Google sebenar dilaporkan disahkan. Sampel CSV di `docs/pbd/examples/` ialah hasil simulasi, bukan data Google.
10. Untuk hosting pada masa hadapan, selepas kelulusan berasingan sahaja: set server environment sebenar (jangan public prefix) dan `PBD_SITE_ORIGIN` origin HTTPS tepat; `PBD_LOCAL_HTTP` mesti tiada/0, `PBD_SIMULATION` tiada/0. Jangan jalankan dev-server di hosting. Adapter Netlify mengimport gateway yang sama; tiada deployment dilakukan sekarang.

## Had keselamatan dan kebolehpercayaan

Identiti murid ialah tiket anonim/peranti, bukan identiti sekolah disahkan. Token rawak, rate limit, validasi payload, action allowlist dan ownership mengehadkan kerosakan; murid berkemahiran teknikal masih boleh mengubah jawapan/metadata bantuan/kemajuan tiket sendiri. Data tersebut ialah respons permainan, bukan bukti identiti atau TP. Skor/statusObjektif2/ulasan tidak boleh dihantar melalui operasi murid. XSS/kompromi peranti/sekolah/rahsia gateway memerlukan mitigasi operasi dan pertukaran rahsia; tiada dakwaan kalis manipulasi sepenuhnya.

Outbox setempat menyimpan penghantaran evidens tanpa audio/kod guru. Jika talian gagal, permainan diteruskan dan penghantaran dicuba semula apabila online/15s; jika localStorage dipadam atau peranti hilang sebelum ack, evidens yang belum dihantar tidak boleh dipulihkan. Jam peristiwa ialah masa diterima pelayan; bagi penghantaran offline, itu bukan anggaran masa sebenar klik. Tarikh mula tiket daripada pelayan kekal. Sheets tiada transaksi merentas dua tab: LockService + upsert idempotent menjadikan retry selamat, namun satu kegagalan pertengahan boleh memerlukan retry untuk melengkapkan unjuran. Jangan menganggap mesej berjaya tanpa ack. Bukti penilaian lama disimpan; game sync tidak menimpa skor.

Untuk skala besar/kuota tinggi, gateway+datastore transaksi dan Sheets sebagai eksport mungkin lebih sesuai; itu bukan fasa ini. Jangan aktifkan atau deploy sehingga pemilik mengesahkan konfigurasi dan ujian Google sebenar.

## Windows — menjalankan ZIP branch work

1. Di GitHub, pilih branch `work` → Code → Download ZIP. Extract All ke folder baharu; jangan jalankan dari dalam ZIP. Pastikan terminal berada dalam folder yang mengandungi `package.json`.
2. Pasang Node.js 22 LTS atau lebih baharu. Buka Command Prompt dalam folder projek (atau VS Code Terminal dengan profil Command Prompt). Semak `node --version`.
3. Salin konfigurasi kosong dengan `copy config\pbd.env.example .env.pbd.local`, kemudian buka `notepad .env.pbd.local`. Isi `APPS_SCRIPT_URL` dengan URL `/exec` sebenar dan `APPS_SCRIPT_PROXY_SECRET` dengan nilai yang sama seperti `NETLIFY_PROXY_SECRET` di Apps Script. Jangan kongsi nilainya.
4. Jalankan `npm run pbd:passcode`, taip kod peribadi 12–200 aksara, kemudian salin hash sahaja ke `PBD_PASSCODE_HASH`. Tetapkan `PBD_GATEWAY_ENABLED=true`, `PBD_SIMULATION=0`, dan `PBD_PORT=4180`. Pelayan setempat menetapkan origin dan pengecualian HTTP loopback sendiri.
5. Jalankan `npm run check`, kemudian `npm test`, kemudian `npm run build`. Teruskan hanya jika semuanya lulus. Tiada pakej runtime pihak ketiga diperlukan untuk aliran ini. Ujian browser berasingan memerlukan Playwright/Chromium.
6. Jalankan `node --env-file=.env.pbd.local scripts/pbd-dev-server.mjs`. Biarkan terminal terbuka dan buka `http://127.0.0.1:4180`. Ini menjalankan frontend DAN kedua-dua backend, bukan Live Server/statik sahaja.
7. Uji dengan tiket murid rekaan baharu. Semak kedua-dua tab sebenar, evidens L4–6, Objektif 2 Belum Dinilai sehingga guru menilai, simpan/muat semula penilaian, logout dan retry. Respons configured=true sahaja bukan bukti sambungan Google berjaya.
8. Berhenti dengan Ctrl+C. Selepas mengubah environment, mulakan semula pelayan. Jika PowerShell menyekat npm.ps1, gunakan Command Prompt atau `npm.cmd`.

Pembetulan keserasian Apps Script: model bersama tidak menggunakan penugasan `??=`/`||=` atau `Array.at()`. Tiga fail `.gs` telah diperiksa menggunakan parser ES2020. Salinan `PbdModel.gs` dan `public/assets/pbd-model.js` mesti kekal sama. Jangan ubah Apps Script milik pemilik secara automatik atau deploy hosting untuk menjalankan ujian ini.
